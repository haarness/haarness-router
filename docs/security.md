# Security model

New self-hosted configurations have no router-key requirement. `auth.enabled`
explicitly selects the mode; an older configuration with `router_key_envs` and
no `enabled` value retains authentication. With authentication disabled, anyone
who can reach the model API can use it. Web UI access controls remain independent.

- Router credentials and provider credentials are different secret domains. The server hashes router keys with SHA-256 at startup and compares digests in constant time. Provider keys remain in `SecretString` containers.
- The embedded Web UI never receives provider secret values or secret environment-variable names. Its overview API exposes only whether a provider credential is configured. A caller-supplied upstream key is held only for its playground request and is never stored by the UI.
- Optional Web UI HTTP Basic credentials are loaded through environment-variable references and compared as SHA-256 digests in constant time. UI responses use `no-store`, `nosniff`, frame denial, referrer denial, and a restrictive Content Security Policy. CORS remains disabled.
- Router keys created in the Web UI are process-local and stored only as SHA-256 digests. Their plaintext is returned once, bootstrap keys cannot be revoked through the UI, state-changing administration calls require a same-origin marker, and all runtime keys disappear on restart.
- At the default `info` level the router writes one `request finished` log line (JSON when standard error is not a terminal) per chat completion request: request ID, the caller's W3C trace ID when a valid `traceparent` arrived, alias (`_direct` for an exact `provider/model`), configured provider, a declared-model or `_undeclared` model label, HTTP status, outcome (`completed`, `failed`, `cancelled`, or `rejected` before any upstream call), the router's error code, fallback count, the provider's own request ID, and duration. The `debug` level adds a `request routed` line with the same labels. No log line contains the model string a client sent, headers, request bodies, prompts, attachments, tool arguments, upstream response bodies, or credentials.
- A caller's `X-Request-ID` is reused when it is 1 to 128 characters of `[A-Za-z0-9._:-]`; otherwise the router generates `req_<UUIDv7>`. Either way the response echoes it in `X-Request-ID`. A `traceparent` counts only in strict W3C form (lowercase hex, non-zero trace and parent IDs, no version `ff`); `tracestate` is ignored.
- Neither the request ID, the trace context, nor any other inbound header is sent to providers. Providers are third parties, and internal identifiers would let them correlate a caller's requests with the operator's own systems and would expose internal naming. Correlate through the provider's own request ID instead (`x-request-id` from OpenAI-compatible APIs, `request-id` from Anthropic, `x-amzn-requestid` from Bedrock), which the summary line records after the same character check. A Gemini call has one only if its response carries one of these headers.
- Prometheus metrics use the same bounded labels and expose active/completed/failed/cancelled streams, bytes, first-event/completion timing totals, fallback attempts, circuit state, and `haarness_router_upstream_failures_total{provider,model,alias,class}`. That counter covers every failed upstream call, including fallback attempts a later target recovered, with class `4xx`, `5xx`, `timeout`, `connect`, or `other`. Every series exists from startup, and only configured providers, declared models, and aliases appear as label values.
- `/metrics` follows the model API's authentication. With authentication enabled it requires `Authorization: Bearer` with a router key or the optional scrape token named by `auth.metrics_token_env`; that token reads metrics and cannot call models. With authentication disabled, the loopback default, `/metrics` is open to anyone who can reach the listener, just like `/v1`. `/healthz` and `/readyz` are always open.
- Configuration contains environment-variable names, not secret values. Missing referenced variables fail startup.
- `X-Upstream-API-Key` is disabled by default. When enabled it requires an exact model and disables alias fallback and configured-key fallback.
- Public attachment URLs must use HTTPS without embedded credentials. Local PDF materialization resolves DNS, rejects any private/loopback/link-local/multicast result, pins a validated public address, disables implicit redirects, and revalidates up to three redirects.
- PDF downloads are limited to 20 MiB and extracted text to 4 MiB. Request bodies default to 32 MiB and SSE frames to 1 MiB.
- HTTP provider URLs require explicit `allow_insecure_http = true` and are intended only for loopback tests.
- CORS is not enabled. The default bind address is loopback.
- A client disconnect drops the response guard, cancels the upstream token, and releases its concurrency permit.

Operational deployment should terminate TLS at a trusted reverse proxy, enable router authentication before exposing the listener beyond loopback (which also protects `/metrics`; give Prometheus the scrape token rather than a router key), enable Web UI Basic authentication (or stronger authentication at the proxy), rotate the UI/router/provider credentials independently, and avoid injecting secrets through command-line arguments or checked-in files. HTTP Basic is suitable only over loopback or HTTPS.
